# Reproduction guide

Repository copies now use central portable paths. Configure [setup_paths_example.m](../matlab/setup_paths_example.m), or ignored matlab/setup_paths.m assigning paths.tumXYZ, paths.tumDesk, paths.resultsRoot and external paths.xyzPWMMatches/paths.deskPWMMatches. Saved repository results are read-only inputs; outputRoot must be beneath ignored reproduction_work. Input resolution prefers generated files, then saved repository files, then configured external excluded PWM files. Use a fresh outputRoot under reproduction_work for an independent run. Parameters, seeds, algorithms and output filenames are unchanged; see [path-only record](path_portability.md).

Both final author-supplied notebooks are included. Confirmed environment is recorded; structural/path checks pass; full experiments were not rerun for packaging and the historical LightGlue revision is unavailable as documented.

1. Download xyz and desk: [dataset setup](dataset_setup.md). No download script exists here.
2. Configure local paths once in setup_paths_example.m or ignored matlab/setup_paths.m. Run repository scripts directly; each locates helpers from its own filename. Dataset roots contain rgb and required groundtruth.txt. resultsRoot defaults to repository results; outputs never default to dataset roots.
3. Generate/use SURF matches: [E_01_export_SURF_raw_matches.m](../matlab/core/E_01_export_SURF_raw_matches.m), or saved SURF_clean_matches.csv/SURF_PWM_matches.csv under results/raw_correspondences/xyz.

Generate raw SuperPoint+LightGlue correspondences with [final xyz exporter](../python/lightglue/fr1_xyz_SuperPoint_LightGlue_export_final.ipynb) and [final desk exporter](../python/lightglue/fr1_desk_SuperPoint_LightGlue_export_final.ipynb). SURF and LightGlue correspondences are generated separately; both are evaluated by the same downstream MATLAB geometric backend. Supply the dataset archives expected by each notebook in Colab. Set paths in the first cell of each notebook; extraction/discovery now use the same configured tree. See [notebook portability](notebook_portability.md) and [structural validation](notebook_structural_validation.md). Scientific code is unchanged except path handling; saved outputs are cleared. ## Portable path behavior

All scripts locate matlab/repository_paths.m relative to their own location. Dataset placeholders, saved resultsRoot, outputRoot under reproduction_work/results, and external PWM file placeholders are centralized. repository_input prefers a regenerated file, otherwise the saved input, then configured external excluded PWM input. repository_output creates fresh output directories under reproduction_work.

Saved results are not overwritten. Output basenames/scientific code remain unchanged. E_18M input discovery now uses the two intended LightGlue filenames, avoiding accidental SURF matches in the reorganized directory; pose logic is unchanged. The legacy journal mechanism scan uses saved mechanism tables. Legacy Figure 8 still needs E_04's shared-backend replacement. Conceptual Figure 1 is a saved asset.
